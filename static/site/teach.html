What helps the model most
  • Real past conversations with the correct outcome. The best single input: they become examples the model copies.
  • A few bad examples, with what went wrong. These become tests the router must pass, never examples to copy.
  • Your policy as concrete rules with numbers (return windows, limits, who is eligible), not marketing prose. Rules need numbers to be checked.
  • FAQ with exact answers. The router can quote them word for word instead of guessing.
  • A list of things that must go to a person. These always win, whatever the model thinks.
  • Trusted sites only. The router looks things up only where you allow it.
  • Remove personal data from samples (names, emails, card and order numbers). The model only needs the shape of the case.
  • Aim for 20–50 good conversations per request type. Fewer works; more beyond that adds little.
  • Keep formats consistent. Same column names in every file, one conversation per line.
