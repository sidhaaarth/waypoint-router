1. Getting started

Waypoint sits between your support app and NVIDIA Nemotron models on Nebius Token Factory. Your app talks to it exactly like it talks to OpenAI, so there's nothing new to learn.

  1. Sign up. Tell us your name, company, use case (email, chat or both) and business type, and paste your Nebius Token Factory API key. Model usage is billed to your own Token Factory account.
  2. Save your router key. You get a key starting with rk-. It's shown once, so keep it somewhere safe. Your app uses it in place of an OpenAI key, and you use it to log in.
  3. Teach your router (optional, recommended). Upload your policies, FAQ and past conversations. See section 3.
  4. Create your first connection. After your first login you're taken straight to setup. See section 4.
  5. Point your app at Waypoint. Change the base URL and key. See section 5.

Logging in and out

Log in with your router key. You stay signed in on that browser until you press Log out; until then, opening the site takes you straight to your dashboard.

2. Run it in your own network

Prefer to keep Waypoint and your data on your own machines? Download it and run it with Docker. The download is the plain app: sign-up, login, onboarding, dashboard, live chat, these docs and the router API. It has no demo data; you bring your own rules and conversations.

Download Waypoint (.zip)

  1. Install Docker Desktop (or Docker with Compose on a server).
  2. Unzip the download and open a terminal in the waypoint folder.
  3. Run docker compose up --build -d.
  4. Open http://localhost:8888/signup, enter your details and your Nebius Token Factory key, and save the router key you get back.
  5. Log in with that key and set up your first connection.

Your projects, keys, history, uploads and memory stay in a Docker volume on your machine and survive restarts. Model calls still go to Nebius Token Factory over HTTPS, because that's where NVIDIA Nemotron runs. The included README.md covers backups, ports and optional settings.

3. Teach your router

The more Waypoint knows about how you handle support, the more messages the small, cheap model can answer correctly. Each kind of upload has one job:

You uploadIt becomesFormat
Policy / rules guideRules that you review before they go liveText, Markdown or a saved web page
Conversations handled wellMemory of past casesJSONL or CSV: message, request_type, reply
Conversations handled poorlyTests, never examplesSame, plus what_went_wrong
FAQStored answersQ: / A: lines, or CSV question,answer
Help-centre / website URLsThe only sites it may look things up onOne URL per line
Must go to a personSafety hand-off topicsOne topic per line
What we help withScope: anything else is handed offA short paragraph

No data yet? Use a starter pack

Waypoint can read a few public help-centre pages for your business type and propose request types, example customer messages, hand-off topics and a scope paragraph. Nothing is saved until you review and accept it.

4. Connections

A connection is one job your assistant does, for example "reply to support emails". Each has its own name, instructions and model settings. Your app picks one with model="connection-name".

Creating a connection

  • Business type unlocks sample files for every field, so you can see the expected format.
  • Connection name: letters, digits and - _ . only, such as support-email.
  • Task description: who writes in, through which channel, the tone you want, and what must go to a person.
  • System prompt (optional): leave it blank and Nemotron Super drafts one for you; you can edit it later.
  • Reference conversations: 20–50 real customer messages with the reply you'd want, covering your most common requests. One JSON object per line:
{"input": "Where is my order #1234?", "expected": "Thanks for reaching out! Your order shipped yesterday..."}

Tuning (calibration)

When you save a connection, Waypoint runs your reference conversations through Nemotron Nano, Super and Ultra and grades each answer against yours. It then picks the cheapest setup that matches the best model's quality on your own examples: Nano with a bigger model as backup, or a bigger model directly if Nano isn't good enough for this job. The Routes page shows what it chose and the accuracy of each model.

You can add more connections any time with New connection on the Routes page.

5. Call it from your app

Use any OpenAI SDK. Change two things: the base URL and the key.

from openai import OpenAI

client = OpenAI(base_url="https://YOUR-WAYPOINT-HOST/v1", api_key="rk-...")
reply = client.chat.completions.create(
    model="support-email",      # your connection name
    user="customer-42",         # optional: tracks cost per customer
    messages=[{"role": "user", "content": "My boots arrived torn, order 4223520702"}],
)
print(reply.choices[0].message.content)
curl https://YOUR-WAYPOINT-HOST/v1/chat/completions \
  -H "Authorization: Bearer rk-..." -H "Content-Type: application/json" \
  -d '{"model": "support-email", "messages": [{"role": "user", "content": "Where is my order?"}]}'

Useful options

  • Photos: send images the standard OpenAI way (an image_url content part, including data: URLs). Waypoint checks the photo matches what the customer says.
  • Conversations: send the whole chat history in messages, and the header x-conversation-id to group turns on your dashboard.
  • Channel: header x-router-channel: email or chat adjusts the reply style.
  • Priority: header x-router-priority: background lets live customer traffic go first when you're near your rate limit.
  • Streaming: stream: true works as usual.
  • Plain model calls: pass a Token Factory model ID as model to skip routing but keep pacing, logging and cost tracking.

What comes back

A standard chat completion. Response headers tell you how it was handled:

x-router-tier, x-router-modelWhich model answered
x-router-escalatedWhether a bigger model took over
x-router-cost-usdWhat this request cost
x-router-fallbackWhether a busy model was swapped for a similar one

6. What happens to a message

Think of a good support desk: a junior agent reads every message, checks the order and the rulebook, and only calls a senior colleague when something is unclear or risky. Waypoint works the same way.

  1. Understand. Nemotron Nano works out what the customer wants, helped by similar past cases from your own data. If it isn't sure, a bigger model double-checks.
  2. Check the facts. Order numbers, emails and account details are looked up in your store. Membership level, address and order status always come from your records, never from what the customer claims.
  3. Apply your rules. Your policies run as plain, predictable rules, so refunds and exceptions follow your rulebook every time.
  4. Take actions. Only the actions your rules allow, such as starting a return. The reply never promises something that didn't happen.
  5. Write the reply. The smallest model that writes well enough for this kind of message. Sensitive cases get a stronger model.
  6. Safety check. Topics you marked "must go to a person", and anything outside your scope, are handed off instead of answered.

Every reply gets a decision record you can open on the dashboard: what was understood, what was checked, which rule applied and which model wrote it.

Around every request

  • Cost control: the cheapest Nemotron model that can do the job answers, and bigger models step in only when needed.
  • Rate limits: requests are paced to your Token Factory limits, so you aren't hit with errors at busy times.
  • Fallback: if a model is busy, the request moves to a similar one instead of failing.
  • Learning: if you opt in, good conversations are added to your memory of past cases each night.

7. The dashboard

  • Overview: traffic, cost, how much stayed on Nano, and what the pipeline decided.
  • Routes: your connections, their tuning results and settings (for example photo checks).
  • Customers: spend per customer (the user field). Set a budget; near it, that customer's answers stay on Nano.
  • Requests: the latest requests, which model answered, and each decision record.
  • Rate limits: how close you are to your Token Factory limits.
  • Settings: your project details, and whether good conversations may be used to grow your memory.
  • Live chat (the chat button): try your connections as a customer would and watch each decision step.

8. Privacy and security

  • Your router key is stored only as a fingerprint (hash), so we can check it but can't read it back.
  • Your Token Factory key is stored encrypted.
  • Uploads stay in your project, are never used to train any model, and can be deleted any time.
  • Learning from your conversations is off until you turn it on.
  • Your login lasts on one browser until you log out.

9. FAQ

Which models does Waypoint use?

NVIDIA Nemotron on Nebius Token Factory: Nano for most work, Super and Ultra when needed, Super-VL for photos.

Do I need to change my app?

Only the base URL, the key and the model name. Anything that works with the OpenAI chat API works here.

What if Nano gets something wrong?

Each connection is tuned so Nano only answers where it matched the best model on your examples. Uncertain cases go to a bigger model, and anything you marked sensitive goes to a person.

I lost my router key.

Keys are shown once and can't be recovered. Sign up again to get a new project and key.
